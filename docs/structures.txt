# Frontend Structure

SCOPE
  TECH:  This map covers tracked source and configuration under frontend-playground/.
         It excludes node_modules/, dist/, and .angular/cache because they are
         installed or generated artifacts.
  PLAIN: This is the maintained map of the frontend; temporary build files are left
         out because they can be recreated.

APPLICATION ROOT
  TECH:  src/main.ts bootstraps the standalone App component with appConfig. App
         renders RouterOutlet, and app.routes.ts lazy-loads every page component.
  PLAIN: The browser starts one Angular application and displays the page selected
         by the current URL.

CORE AREA
  TECH:  src/app/core centralizes shared API contracts, HTTP services, route guards,
         the JWT interceptor, clock synchronization, and persisted selections.
  PLAIN: Shared security and data logic lives in one place so pages do not duplicate
         it.

AUTH FEATURES
  TECH:  src/app/features/auth contains standalone reactive-form pages for login and
         registration; guestGuard prevents authenticated users reopening them.
  PLAIN: Signed-out users can sign in or create an account here.

DASHBOARD FEATURES
  TECH:  src/app/features/dashboard contains authenticated profile, SuperAdmin audit
         logs, and the composed world-clock feature.
  PLAIN: Signed-in users can view their account and clocks, while SuperAdmins also
         receive an audit tool.

WORLD CLOCK COMPOSITION
  TECH:  WorldClockPage coordinates SearchBar, ClockList, ClockListItem, WorldMap,
         DetailPanel, and WorldClockFooter with ClockService and SelectionStore.
  PLAIN: The world-clock page combines search, a clickable map, saved clocks, hover
         details, and synchronization status into one screen.

PUBLIC ASSETS
  TECH:  public/ is copied unchanged by Angular. world.geojson drives SVG paths;
         the remaining files provide branding and authentication visuals.
  PLAIN: These are the images and map data downloaded directly by the browser.

ROUTE STRUCTURE
  TECH:  /login and /register use guestGuard; /profile and /world-clock use
         authGuard; /audit-logs also requires roleGuard('SuperAdmin'). Empty and
         wildcard paths redirect to /profile.
  PLAIN: Visitors must sign in for dashboard pages, and only SuperAdmins can inspect
         audit logs.
