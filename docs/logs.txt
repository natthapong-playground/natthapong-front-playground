# Documentation Changelog

2026-07-27 - Soften the profile card and improve text contrast
  TECH:  Replaced the nearly opaque profile surface with translucent navy glass in
         ocean mode and translucent white in light mode, with explicit Material
         on-surface colors for readable titles, details, and secondary text.
  PLAIN: The profile card is less bright, reveals more of the background, and keeps
         the account name easy to read in both appearances.

2026-07-27 - Add a persisted ocean and white theme to non-map pages
  TECH:  Added UiThemeService with ocean/light signals and ui.theme.v1 persistence;
         connected accessible toggle buttons and responsive theme styling to login,
         registration, profile, and audit logs. Ocean remains the default and all
         world-map components and styles remain unchanged. Unit coverage verifies
         default, restored, and toggled values.
  PLAIN: Users can switch account and audit pages between the blue ocean look and a
         clean white look, and the browser remembers their choice. The map is unchanged.

2026-07-27 - Replace the authentication GIF with map-toned CSS effects
  TECH:  Removed public/backgrounds/auth-bg.gif and rebuilt both auth backgrounds
         from navy/azure/cyan gradients matching WorldMap, a masked animated grid,
         drifting glow rings, translucent card treatment, and reduced-motion rules.
  PLAIN: Login and registration now share a lightweight animated blue background
         inspired by the world map, without downloading a large GIF.

2026-07-27 - Add Google login and registration alongside local accounts
  TECH:  Added a reusable Google Identity Services button to both auth pages, a
         public googleClientId environment setting, and AuthService /google-login
         exchange using the existing JWT persistence flow. The auth interceptor now
         treats Google login as a credential endpoint. Empty configuration hides the
         optional choice, failed GIS loads can be retried, late callbacks are ignored,
         and production builds select their own environment file. Focused tests cover
         configuration, credential exchange, and destroyed-component callbacks.
         Button sizing works on desktop and mobile without adding a frontend package.
         Both Angular environments now contain the configured public OAuth Web Client
         ID, enabling the Google button at runtime.
  PLAIN: Users can now sign in or create an account with their own Google account,
         while the original email-and-password buttons remain available.

  PLAIN: Windows users can now set up and start the app without installing tools on
