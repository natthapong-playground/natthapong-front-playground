# Frontend Methods, Signals, Routes, and APIs

== Windows project scripts ==

setup.bat
  TECH:  Validates the checkout, maps x64/ARM64/x86 to pinned Node.js archive hashes,
         downloads and verifies Node.js 22.23.1 under .venv/, installs npm 11.11.0
         there, scopes npm cache/config, temp, home, and node-gyp data to .venv/, runs
         npm ci in frontend-playground/, and stores the package-lock.json SHA-256;
         any failed stage returns a nonzero exit code.
  PLAIN: Prepares the Windows project without installing tools globally and directs
         its setup files and working data into the repository's ignored local folder.

start.bat [Angular serve options]
  TECH:  Finds the architecture-specific local Node executable, bootstraps missing
         tools or lockfile-stale dependencies through setup.bat, scopes writable tool
         paths under .venv/, prepends only that Node directory to the process PATH,
         and forwards arguments to npm start.
  PLAIN: Starts the website with the isolated tools and can accept options such as a
         different port.

== Bootstrap and routes ==

bootstrapApplication(App, appConfig)  [src/main.ts]
  TECH:  Starts the standalone root component with router, HttpClient, interceptor,
         and browser error-listener providers; rejected startup logs to console.
  PLAIN: Starts the frontend and reports if Angular cannot initialize it.

appConfig.providers  [src/app/app.config.ts]
  TECH:  Registers provideBrowserGlobalErrorListeners(), provideRouter(routes), and
         provideHttpClient(withInterceptors([authInterceptor])).
  PLAIN: Makes routing, API requests, and authentication handling available app-wide.

route /login  [src/app/app.routes.ts]
  TECH:  guestGuard-protected lazy route loading Login.
  PLAIN: Opens sign-in only for visitors who are not already signed in.

route /register  [src/app/app.routes.ts]
  TECH:  guestGuard-protected lazy route loading Register.
  PLAIN: Opens account creation only for signed-out visitors.

route /profile  [src/app/app.routes.ts]
  TECH:  authGuard-protected lazy route loading Profile.
  PLAIN: Shows account information after the user signs in.

route /audit-logs  [src/app/app.routes.ts]
  TECH:  Lazy route loading AuditLogs after authGuard and
         roleGuard('SuperAdmin') both pass.
  PLAIN: Allows only signed-in SuperAdmins to inspect backend activity.

route /world-clock  [src/app/app.routes.ts]
  TECH:  authGuard-protected lazy route loading WorldClockPage.
  PLAIN: Opens the interactive clocks for signed-in users.

routes / and **  [src/app/app.routes.ts]
  TECH:  Empty and unmatched URLs redirect to /profile; authGuard on /profile then
         redirects unauthenticated users to /login.
  PLAIN: Sends visitors to the main account page or sign-in instead of a dead end.

== Authorization and HTTP interception ==

authGuard: CanActivateFn  [core/guards/auth.guard.ts]
  TECH:  Returns true when AuthService.isAuthenticated() is true; otherwise returns
         Router.createUrlTree(['/login']).
  PLAIN: Prevents signed-out visitors from opening protected pages.

guestGuard: CanActivateFn  [core/guards/auth.guard.ts]
  TECH:  Redirects authenticated users to /profile and allows other visitors.
  PLAIN: Keeps signed-in users from returning to sign-in and registration screens.

roleGuard(...roles: Role[]): CanActivateFn  [core/guards/auth.guard.ts]
  TECH:  Requires authentication and a decoded currentRole included in roles;
         failures redirect to /login or /profile as appropriate.
  PLAIN: Restricts sensitive pages to approved account roles.

isAuthEndpoint(url: string): boolean  [core/interceptors/auth.interceptor.ts]
  TECH:  Tests the URL against /login, /google-login, /refresh-token, and
         /users/register so their 401 responses do not trigger refresh attempts.
  PLAIN: Recognizes requests where a 401 means the credentials themselves failed.

authInterceptor: HttpInterceptorFn  [core/interceptors/auth.interceptor.ts]
  TECH:  Clones requests with the current bearer token. On an eligible 401 it calls
         refreshToken(), retries once with the new access token, and logs out if
         refresh or retry fails; unrecoverable authenticated 401s also log out.
  PLAIN: Adds authentication to API calls and silently renews expired sessions when
         possible.

== AuthService ==

AuthService.token: Signal<string | null>
  TECH:  Read-only view of the access token initialized from localStorage.
  PLAIN: Lets the application react to the current session token.

AuthService._token: WritableSignal<string | null>
  TECH:  Private writable source initialized by readToken() and exposed through the
         read-only token signal.
  PLAIN: Holds the session token internally while preventing pages from changing it.

AuthService.isAuthenticated: Signal<boolean>
  TECH:  Computed signal that decodes token exp and requires expiration to be later
         than Date.now(). Missing, malformed, or expired tokens return false.
  PLAIN: Reports whether the stored login is still valid.

AuthService.currentRole: Signal<Role | null>
  TECH:  Computed signal returning the decoded JWT role or null.
  PLAIN: Identifies which permissions the signed-in user has.

AuthService.login(email: string, password: string): Observable<TokenResponse>
  TECH:  POSTs URL-encoded username/password to /login and persists the returned
         access and refresh token pair through saveTokens().
  PLAIN: Signs in with email and password and remembers the new session.

AuthService.loginWithGoogle(credential: string): Observable<TokenResponse>
  TECH:  POSTs `{credential}` to /google-login and persists the returned access and
         refresh token pair through saveTokens().
  PLAIN: Exchanges Google's proof for the same application session used by password
         login.

AuthService.refreshToken(): Observable<TokenResponse>
  TECH:  POSTs the stored refresh token to /refresh-token, saves rotated tokens, and
         shares one in-flight request via shareReplay(1); missing tokens error early.
  PLAIN: Renews an expired session once even when several API calls fail together.

AuthService.logout(): void
  TECH:  Captures tokens, clears local storage and signal state, navigates to /login,
         then best-effort POSTs /logout with bearer and optional refresh token.
  PLAIN: Signs out immediately in the browser and asks the backend to revoke the
         entire session.

AuthService.register(
  email: string, password: string, role: Role = 'Regular'
): Observable<TokenResponse>
  TECH:  POSTs /users/register and switchMaps a successful response into login().
  PLAIN: Creates a Regular account by default and signs the new user in.

AuthService.saveTokens(res: TokenResponse): void
  TECH:  Private helper storing access_token and refresh_token best-effort in
         localStorage before updating the reactive token signal.
  PLAIN: Remembers successful authentication and updates the screen immediately.

AuthService.clearTokens(): void
  TECH:  Private helper removing both token keys best-effort and setting token null.
  PLAIN: Removes the local session even if browser storage is unavailable.

AuthService.readToken(): string | null
  TECH:  Private access_token storage reader returning null when localStorage throws.
  PLAIN: Safely retrieves the remembered access token.

AuthService.readRefreshToken(): string | null
  TECH:  Private refresh_token storage reader returning null when localStorage throws.
  PLAIN: Safely retrieves the remembered refresh token.

AuthService.decodeToken(token: string): JwtPayload | null
  TECH:  Private Base64URL JWT payload decoder with padding normalization and a null
         fallback for malformed values; it does not cryptographically verify JWTs.
  PLAIN: Reads expiration and role details from a token without crashing on bad data.

== SelectionStore ==

SelectionStore.codes: Signal<string[]>
  TECH:  Read-only signal initialized by load() from world-clock.codes.v1.
  PLAIN: Exposes the list of countries selected for live clocks.

SelectionStore._codes: WritableSignal<string[]>
  TECH:  Private writable source initialized by load() and exposed through codes.
  PLAIN: Holds selected country codes internally so only store methods can change them.

SelectionStore.add(code: string): void
  TECH:  Uppercases code, skips duplicates, appends immutably, and calls persist().
  PLAIN: Adds one country to the saved clock list without duplicates.

SelectionStore.remove(code: string): void
  TECH:  Uppercases code, filters it from the signal value, and calls persist().
  PLAIN: Removes one country from the saved clock list.

SelectionStore.has(code: string): boolean
  TECH:  Performs a case-insensitive membership check against current codes.
  PLAIN: Reports whether a country's clock has already been selected.

SelectionStore.load(): string[]
  TECH:  Private helper parsing localStorage JSON, retaining only strings, and
         uppercasing them; malformed or unavailable storage produces an empty list.
  PLAIN: Restores safe country selections when the page starts.

SelectionStore.persist(): void
  TECH:  Private best-effort JSON write of current codes to localStorage.
  PLAIN: Remembers clock choices for a later visit when browser storage permits it.

== ClockService ==

ClockService.syncing: WritableSignal<boolean>
  TECH:  Public status signal tracking whether a clock request is active.
  PLAIN: Lets the page show when clocks are updating.

ClockService.error: WritableSignal<string | null>
  TECH:  Public status signal containing a stale-data message after sync failure.
  PLAIN: Lets the page explain that clocks could not refresh.

ClockService.snapshot: WritableSignal<ClockSnapshot | null>
  TECH:  Private source holding the latest synchronized reference and country list.
  PLAIN: Keeps the most recent clock data available between backend refreshes.

ClockService.ticker: WritableSignal<number>
  TECH:  Private counter incremented once per second to invalidate the now computed.
  PLAIN: Causes every visible clock to advance once per second.

ClockService.countries: Signal<Country[]>
  TECH:  Computed signal returning snapshot countries or an empty array.
  PLAIN: Supplies the current selected-country clock rows.

ClockService.referenceUtc: Signal<string | null>
  TECH:  Computed signal returning the latest backend referenceUtc timestamp.
  PLAIN: Supplies the last synchronization time shown in the footer.

ClockService.now: Signal<Date>
  TECH:  Computed from the latest server reference instant plus browser elapsed time;
         a ticker dependency causes one recomputation per second.
  PLAIN: Advances all displayed clocks together between backend synchronizations.

ClockService.constructor()
  TECH:  Creates a selection effect, one-second tick timer, 60-second visible-tab
         poller, and visibilitychange listener; DestroyRef removes all resources.
  PLAIN: Starts clock updates and cleans them up when the service is destroyed.

ClockService.refresh(): void
  TECH:  Public method forcing resync() with current SelectionStore codes.
  PLAIN: Immediately asks the backend for fresh clock data.

ClockService.resync(codes: string[]): void
  TECH:  Private method using a local empty snapshot when codes is empty; otherwise
         calls getClock(), updates status, applies success, or retains stale data and
         exposes an error message.
  PLAIN: Refreshes selected clocks without blanking the last known times on failure.

ClockService.applySnapshot(snap: ClockSnapshot): void
  TECH:  Private helper records server and browser timestamps and updates snapshot.
  PLAIN: Establishes the reference point used to advance all clocks locally.

DetailPanel.localTime: Signal<string | null>
  TECH:  Computed zoned time matching ClockListItem or null without a country.
  PLAIN: Shows the hovered country's live local time when available.

WorldClockFooter.referenceUtc: InputSignal<string | null>
  TECH:  Component input with a null default for the latest server timestamp.
  PLAIN: Supplies the timestamp of the latest clock synchronization.

WorldClockFooter.lastUpdated: Signal<string | null>
  TECH:  Computed localized date-time label that rejects absent or invalid dates.
  PLAIN: Shows a readable update time only when the backend value is valid.

== WorldMap ==

WorldMap.selectedCodes: InputSignal<string[]>
  TECH:  Component input with an empty default for selected country codes.
  PLAIN: Tells the map which saved countries to highlight.

WorldMap.showGrid: InputSignal<boolean>
  TECH:  Component input with a false default controlling timezone-band visibility.
  PLAIN: Tells the map whether to draw the timezone grid.

WorldMap.now: InputSignal<Date>
  TECH:  Component input with a creation-time default used for UTC-band labels.
  PLAIN: Supplies the current instant used by timezone labels.

WorldMap.hover: OutputEmitterRef<string | null>
  TECH:  Emits a debounced country code or null after map pointer movement.
  PLAIN: Tells the page which country the user is exploring.

WorldMap.select: OutputEmitterRef<string>
  TECH:  Emits a non-null country code when a recognized map shape is clicked.
  PLAIN: Tells the page which country clock the user wants to add.

WorldMap.shapes: WritableSignal<MapShape[]>
  TECH:  Stores projected SVG paths built from the loaded GeoJSON collection.
  PLAIN: Supplies the country outlines drawn on the map.

WorldMap.hovered: WritableSignal<string | null>
  TECH:  Stores the code currently highlighted immediately under the pointer.
  PLAIN: Highlights the country beneath the pointer without waiting for API details.

WorldMap.bands: Signal<TimeZoneBand[]>
  TECH:  Computes 24 whole-hour longitude bands from UTC-12 through UTC+11 when
         showGrid is true, otherwise returns an empty array.
  PLAIN: Supplies current labels and lines for the optional timezone grid.

WorldMap.selectedSet: Signal<Set<string>>
  TECH:  Private computed set of uppercased selectedCodes used for fast map lookups.
  PLAIN: Lets the map quickly decide which countries should appear selected.

WorldMap.constructor()
  TECH:  GETs /world.geojson with takeUntilDestroyed(), transforms success through
         buildShapes(), and uses an empty shape list on failure.
  PLAIN: Loads the local map when the component starts.

WorldMap.isSelected(code: string | null): boolean
  TECH:  Checks a computed uppercase Set while safely rejecting null country codes.
  PLAIN: Determines which map countries should be highlighted as saved.

WorldMap.onEnter(shape: MapShape): void
  TECH:  Updates immediate hover state and schedules the shape's debounced code.
  PLAIN: Begins showing details when the pointer enters a country.

WorldMap.onLeave(): void
  TECH:  Clears immediate hover state and schedules a debounced null hover output.
  PLAIN: Removes country details after the pointer leaves the map.

WorldMap.onClick(shape: MapShape): void
  TECH:  Emits shape.code through select when the code is non-null.
  PLAIN: Adds a clock when the user clicks a recognized country.

WorldMap.scheduleHover(code: string | null): void
  TECH:  Private method replacing the prior timeout and emitting after 100 ms.
  PLAIN: Avoids excessive API lookups while the pointer moves quickly across borders.

WorldMap.buildShapes(geo: FeatureCollection): MapShape[]
  TECH:  Private Polygon/MultiPolygon flattener that normalizes ISO codes, builds SVG
         path strings, assigns deterministic shades, and removes empty paths.
  PLAIN: Converts geographic country data into shapes the browser can draw.

WorldMap.ringToPath(ring: Ring): string
  TECH:  Private equirectangular projection from longitude/latitude into a 1000x500
         SVG viewBox, returning a closed path or empty string.
  PLAIN: Converts one country outline from earth coordinates to screen coordinates.

WorldMap.shadeFor(key: string): number
  TECH:  Private deterministic 31-based unsigned hash returning one of five shades.
  PLAIN: Gives neighboring map shapes visual variety without storing extra color data.

== HTTP API and storage summary ==

API base URL
  TECH:  Active imports use environment.apiUrl, currently
         http://127.0.0.1:8000/api/v1 in every build configuration.
  PLAIN: The application currently expects a backend running locally on port 8000.

Backend endpoints
  TECH:  POST /login, /google-login, /refresh-token, /logout, /users/register; GET
         /users/myprofile, /audit-logs, /countries, /countries/{code}, and /clock.
  PLAIN: These backend operations support accounts, profiles, audits, countries, and
         synchronized clocks.

Browser storage keys
  TECH:  access_token, refresh_token, world-clock.codes.v1,
         world-clock.showSearch, and world-clock.showGrid.
  PLAIN: The browser remembers the session, selected countries, and two display
         preferences.
